# Kinora

Веб-приложение для совместного просмотра: комната по ссылке, синхронное видео, голос и чат.

## Запуск

Нужны Python 3.11+ и Node.js 20+.

**Одной командой (Windows):** двойной клик по `start.bat`, затем открыть http://localhost:8000.

**Режим разработки** (горячая перезагрузка), в двух терминалах:

```bash
# 1 — сервер
cd backend
py -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python -m uvicorn app.main:app --reload --port 8000

# 2 — интерфейс
cd frontend
npm install
npm run dev        # http://localhost:5173
```

## Что умеет

- **Комнаты по ссылке** без регистрации: имя + цвет аватара. Есть ведущий, модераторы и режимы «управляют все» / «только ведущий». Можно выгнать участника.
- **Синхронный просмотр**: play, пауза, перемотка, очередь видео, автопереход к следующему.
  - Опоздавшие догоняют автоматически.
  - После обрыва связи клиент переподключается и сохраняет роль 60 секунд.
  - Опция «ждать отстающих».
- **Источники**:
  - каталог из 31 фильма Internet Archive;
  - YouTube;
  - VK Видео (официальный плеер с JS API);
  - Telegram (посты публичных каналов и групп);
  - Vimeo;
  - прямые ссылки `.mp4`, `.webm`, `.m3u8`;
  - проверка ссылки до запуска.
- **Голос**: WebRTC P2P до 6 человек.
  - Выбор микрофона, mute, push-to-talk (V).
  - Громкость каждого участника.
  - Индикатор говорящего.
  - Автоприглушение фильма, когда кто-то говорит.
- **Чат и реакции**, лимиты на флуд, сообщения поверх видео в полноэкранном режиме и режиме кинотеатра.
- **Горячие клавиши**: пробел — пауза, ←/→ — ±10 с, M — звук, F — полный экран, T — кинотеатр, C — чат.

## Как устроено

```
frontend/  React + Vite + TypeScript + Tailwind
  src/lib/players/   адаптеры плееров (YouTube, VK, Vimeo, HTML5/HLS) — единый интерфейс
  src/lib/sync.ts    синхронизация: часы сервера, коррекция дрейфа (скорость/seek)
  src/lib/voice.ts   голос: WebRTC mesh, сигналинг через WebSocket
  src/room/          экран комнаты
backend/   FastAPI
  app/rooms.py       комнаты, протокол, права (состояние в памяти + снимок в БД)
  app/sources.py     адаптеры источников: распознать ссылку, проверить встраивание
  app/db.py          SQLite (сессии, комнаты, каталог, чат, жалобы)
  scripts/build_catalog.py   пересобрать каталог из Internet Archive
```

- **Видео не идёт через сервер.** Каждый зритель грузит его прямо с источника, а сервер только хранит состояние: `{status, position, ref_time, version}`.
- **Синхронизация.** Клиент вычисляет ожидаемую позицию по часам сервера. Если расхождение больше 0.35 с, плеер подстраивает скорость на 5–10%; если больше 2 с — перематывает.
- **Новый источник** = класс в `app/sources.py` + класс в `src/lib/players/` + строка в реестре.

## Добавить фильмы в каталог

Допиши `identifier` с archive.org в `backend/scripts/build_catalog.py` и запусти:

```bash
cd backend
.venv/Scripts/python scripts/build_catalog.py
```

Каталог загрузится в БД при следующем старте сервера.

## Голос через интернет

Микрофон в браузере работает только на `https://` или `localhost`.

Если у кого-то голос не соединяется (строгий NAT), нужен TURN-сервер. Его адрес и доступ задаются переменными окружения:

```
KINOZAL_TURN_URL=turn:example.com:3478
KINOZAL_TURN_USER=...
KINOZAL_TURN_PASS=...
```

## Большие фильмы из Telegram (бот)

Telegram не отдаёт сайтам большие файлы, поэтому их достаёт бот через MTProto (до 2 ГБ и больше).

- Перешли видео боту → он создаст комнату и пришлёт ссылку.
- Или вставь на сайте ссылку `t.me/канал/123` на большой файл из публичного канала.

Видео идёт через сервер кусками по 512 КБ, с поддержкой перемотки и кэшем на диске.

Настройка (переменные окружения):

```
TG_BOT_TOKEN=123456:ABC...   # от @BotFather
TG_API_ID=1234567            # https://my.telegram.org → API development tools
TG_API_HASH=0123abcd...
KINOZAL_DB=/data/kinozal.db  # база, сессия бота и кэш — на постоянном диске
TG_SESSION=/data/tgbot
TG_CACHE_DIR=/data/tgcache
TG_CACHE_GB=3                # предел кэша видео
```
